# VAOS application function catalogue

This catalogue documents the significant public service functions and HTTP entry points in the current source tree. It is intended for maintainers and integrators; it does not promise that a separately running installation has loaded this checkout. Private helpers (names beginning with `_`) are implementation details unless explicitly called out in a feature-specific catalogue.

## How to read the contracts

- [`API.md`](API.md) is the human-readable inventory of REST operations, purpose, access rules, limits, and common errors. It includes the browser compatibility routes and the non-OpenAPI token/integration administration routes.
- The running source build's `/api/openapi.json` is the field-level contract for versioned REST operations: path/query parameters, request and response schemas, and declared authorization. `/api/docs` renders that schema for signed-in administrators.
- [`MCP.md`](MCP.md) lists agent tools/resources, their inputs, outputs, policy checks, approval behavior, and limits. MCP wrappers call the REST API rather than bypassing it.
- [`observability/source-function-catalogue.md`](observability/source-function-catalogue.md) is the detailed Feature 8 catalogue for telemetry, storage, reporting, SIEM delivery, and instrumentation.

Unless a function is explicitly described as a route or public pure service below, it is an internal application function. Admin HTTP handlers use the `require_admin` dependency (dashboard Basic authentication or an enabled API token with matching scope/group, where that route is in the API schema); settings, token creation/revocation, and human MCP approvals deliberately use Basic authentication. Camera and invitation flows use scoped capability tokens and consent checks. Errors are returned using the route's documented HTTP status and FastAPI `detail` shape; callers should not infer success from a request being accepted if the response says a job is queued or approval is required.

## Application services

| --- | --- | --- | --- |
| `model_runtime_status()` — `main.py` | Summarizes the configured detector/runtime state. No arguments. | JSON-ready status fields for model/runtime availability. | Reads local model/runtime state; internal diagnostics and admin status routes. Missing or unusable model files are reported as unavailable rather than silently treated as a working detector. |
| `get_object_detector()` — `main.py` | Loads or returns the configured object detector. No arguments. | Cached detector/runtime object or unavailable state handled by the caller. | Model files and the installed inference runtime; internal inference path. Model/runtime initialization failures are handled by the caller and reflected in runtime status. |
| `detect_faces(image)`, `feature_for_face(image, face, recognizer)`, `extract_enrollment_embedding(content)`, `find_best_match(embedding, threshold)` — `main.py` | Detects faces, derives embeddings from image/face inputs, and finds a threshold-qualified stored match. | Detection data, embedding arrays/encodings, or `(person_id, display_name, score)` / `None`. | Face-recognition runtime plus existing participant data. Used only behind the enrollment/camera workflows; invalid images or unavailable runtimes follow the calling route's validation/service-error response. Face matching is not an identity guarantee. |
| `process_frame(token, content)` — `main.py`; `receive_frame(token, request)` — `camera_service.py` | Processes one camera JPEG frame using a camera capability token. | Detection/recognition response and permitted activity/sample metadata. | Model runtime, camera token, engine settings and application database. Public camera route validates capability and media type; invalid/revoked token, invalid frame, or unavailable model returns an error and does not grant admin access. |
| `process_video_review_frame(token, content, source_time_seconds, save_samples)` — `main.py` | Runs one timestamped local-video frame through the existing detector/review-sample path. | Frame analysis and optional sample metadata. | Selected model, review-session state and sample store; reached through the authenticated Video Review API. Invalid session/time/frame and conflicting operations are rejected by the route. |
| `validate_rule(payload)` — `tracking_rules.py` | Validates and normalizes one count-in-region or dwell-in-region rule. | Normalized dictionary, including class, confidence, region, camera scope, cooldown and optional dwell duration. | Pure Python, no database or network. Raises `ValueError` with a field-level explanation for unsupported or out-of-range values. |
| `evaluate_rules(*, rules, camera_token, objects, frame_size, state, now, tracking_enabled)` — `tracking_rules.py` | Evaluates detections and short-lived process-local track IDs against active rules. | List of metadata-only alert dictionaries; updates the supplied ephemeral state. | Existing camera inference/tracker supplies the inputs. | `build_hardware_report(*, system_metrics, device_inventory, inference_runtime, training_state, data_dir)` — `hardware_intelligence.py` | Converts measurements already collected by VAOS into hardware facts and non-binding guidance. | JSON-ready inventory, measured telemetry, availability and recommendations. | Caller-supplied telemetry and local filesystem capacity; does not import PyTorch, initialize CUDA, benchmark, or change settings. | `validate_local_yolo_dataset(source_path, progress_callback=None)` — `main.py` | Checks a local dataset's detector layout, YAML, image/label pairing and class/annotation totals. | Validation report and counts/progress. | Local filesystem and dataset parser. Used by authenticated dataset preparation; malformed, incomplete or conflicting datasets are reported as not ready rather than added as usable training choices. |
| `prepare_local_dataset(payload, admin)` / `purge_managed_dataset(dataset_id, payload, admin)` — `main.py` | Start supported local dataset validation/conversion or request deletion of a managed prepared copy. | Accepted job/status response or deletion result. | Managed dataset registry, configured allowed roots, background worker and disk. Admin control access; active training/preparation conflicts are rejected, and purge applies the route's ownership/path checks and confirmation rules. | `run_ml_training(device_choice, dataset_source, initial_model="auto", resource_mode=False, requested_epochs=None)` / `start_ml_training(payload, admin)` / `stop_ml_training(admin)` — `main.py` | Run function executes the training worker; start validates and queues a run; stop requests a safe stop at the supported checkpoint boundary. | Worker writes run/epoch history; route returns accepted state or stop result. | Ultralytics/PyTorch runtime, chosen model, prepared dataset, GPU/CPU and local training state. | `list_ml_training_history(run_id=None, admin)` / `batch_review_ml_samples(payload, admin)` — `main.py` | Read run summaries/per-epoch metrics, or apply one review decision to a bounded selected sample set. | Paginated/filtered history or per-sample review outcomes. | Local training/review database. | `build_combined_coco_reviewed_yaml(...)`, `build_combined_uvh_reviewed_yaml(...)`, `build_combined_coco_uvh_kaggle_reviewed_yaml(...)` — `main.py` | Build temporary detector dataset configurations combining supported prepared sources and reviewed samples. | Dataset YAML/class mapping and source-count information (UVH variant also returns its additional count). | Validated source annotations, class mapping and reviewed sample store. ## Error handling and permissions summary

- Validate caller-controlled values at the HTTP or service boundary. Pure validators raise `ValueError` (or the domain exception); route handlers convert these to documented HTTP errors.
- Authentication/scope failures remain 401/403; absent or ownership-hidden records return 404; conflicting jobs/invalid approval state can return 409; oversized and unsupported uploads return 413/415; schema errors return 422; model/service unavailability may return 503; MCP writes waiting for approval return 428; throttling returns 429. The exact route contract takes precedence over this summary.
- Never log API tokens, passwords, camera/enrollment capability tokens, raw face images, or unredacted private event payloads. Correlation IDs assist request matching and are not authentication or universal distributed trace IDs.
- Background work being accepted or queued is not proof it completed. Read its job/training state and terminal result.

## Updating this catalogue

When adding, removing, or changing a public function or route, update the corresponding feature guide and `API.md`/`MCP.md`, verify generated OpenAPI and permissions, then update this catalogue's entry point and error behavior. Private helpers should be documented only when they carry a security, persistence, recovery, or cross-process invariant that maintainers must preserve. The observability-specific catalogue contains those Feature 8 invariants.
