# VAOS feature catalogue

This catalogue reflects the v1.1.0 candidate source and evidence reviewed through 2026-11-16 (code commit `9127524`, validated in CI run `43766504519`) and is intentionally honest about gaps. “Implemented” means present in code; it does not imply production validation. By product-owner scope decision on 2026-11-12, AI Model Arena and Ready-to-Run Vision Applications are deferred beyond v1.1.0 and are not current-release deliverables. See [project status](PROJECT_STATUS.md) and the [release-readiness report](RELEASE_READINESS_1.1.0.md) for current evidence and the release decision.

## Deferred beyond v1.1.0

- **AI Model Arena:** intentionally excluded from this release. No Arena page, comparison API/MCP tool, CLI command, or Arena-specific report is offered. The earlier safety review is retained as historical planning material only.
- **Ready-to-Run Vision Applications:** intentionally excluded from this release. No template gallery, template API/MCP operation, or template bundle is offered. Existing Video Review and other working VAOS features remain in scope and are retained.

## Implementation progress after baseline audit

Updated 2026-11-12 against the working tree after the read-only reviews:

- Added a dual-gated sensitive-read permission. Sensitive profile, camera/tunnel, event, and review-image reads require a Settings-wide switch plus a token-specific grant; new tokens remain diagnostics-only by default.
- Added the MCP approval inbox and exact-request approval API. MCP-designated tokens cannot execute writes until a Basic-authenticated administrator approves the request. Approvals expire after 10 minutes, bind to the token and request fingerprint, reject changed parameters, and are consumed once. Multipart file content is fingerprinted canonically without retaining the file or filename in the approval record.
- Fixed a method-initialization error in the MCP authorization check and added isolated security/bridge tests plus GitHub Actions checks.
- Added the official Apache 2.0 `LICENSE` and a README license statement. Third-party models, datasets, and dependencies retain their own terms.
- Added a searchable, schema-driven `/api-explorer` page that reads the live OpenAPI contract, sends only same-origin requests, asks before writes, and keeps any entered API token in page memory only. Multipart and raw-file inputs follow the published contract where available.
- Added a dedicated Hardware page and authenticated `/api/admin/hardware` endpoint, reusing VAOS telemetry. The shared collector now preserves existing GPU 0 dashboard fields and returns measured rows for all NVIDIA GPUs. CUDA detection, runtime confirmation, and active inference are reported separately; recommendations are estimates and are never applied.
- Added isolated hardware report tests and Phase 1 feature guides. No GPU benchmark or service restart was run while the 50-epoch training log was advancing.
- Added a Tracking & Event Rules page and API that reuse shared detections and the short-lived tracker. Rules support count-in-region and dwell-in-region, consecutive-frame confirmation, camera scope, cooldown, and metadata-only event history capped at 5,000 rows. The feed is separate from existing face sightings and object-class summaries.
- Added pure tracking-rule tests and API authorization/MCP approval cases. At the time of that implementation note, the repository suite passed 132 tests in 16.160 seconds; the 13 November checkpoint had 222 passing repository-wide tests. The newer 300-test evidence is recorded in [project status](PROJECT_STATUS.md); see [validation](observability/validation.md) for detailed history. No real camera test or service activation was attempted.
- Added configuration-only Project Bundles with strict member allowlisting, checksum and schema validation, bounded reads, preview-only import, separate save/apply steps, and security/MCP checks. At the time of that implementation note, the repository suite passed 132 tests in 16.160 seconds; the 13 November checkpoint had 222 passing repository-wide tests. The newer 300-test evidence is recorded in [project status](PROJECT_STATUS.md); see [validation](observability/validation.md) for detailed history. Bundles intentionally do not include model/data files or sensitive runtime state.
- Added creator attribution through the single application metadata source, an About page and subtle dashboard footer, citation metadata, and linked documentation credits. Static inspection shows the profile URLs are wired; LinkedIn automated access returned HTTP 999, and no desktop/mobile browser session against the source build was run.

These changes improve API/MCP safety but do not complete the currently scoped v1.1.0 feature set or change the NO-GO staging decision. The two deferred items are not current-release deliverables. See [testing](TESTING.md) and [project status](PROJECT_STATUS.md).

### Cross-process training-log safety follow-up (13 November 2026)

Training-log appends, rotation and retained-history reads now take an OS-level sidecar lock in addition to the existing thread lock. This serializes multiple VAOS worker processes using one local data directory and avoids concurrent rename/append races. A four-process test forced rotation on every append and verified all 20 retained JSONL records remained parseable and unique; the live log reader also skips malformed entries without hiding neighboring valid progress records. The full suite at that 13 November checkpoint passed 222 tests; the newer candidate test result is recorded in [project status](PROJECT_STATUS.md). Network/cloud filesystem lock behavior and abrupt OS-level failures remain unverified; release remains NO-GO.
