### Overlap conclusion

VAOS already has live diagnostics, hardware telemetry, training logs/history, token-access records, MCP approvals, generated OpenAPI and SQLite persistence. Feature 8 should unify and extend these sources. It should not build a second dashboard, sampler, authentication system, training-history store or independent exporter.

## Target architecture

1. A code-owned metric catalogue defines metric key, display name, unit, type, formula/source, dimensions, aggregation, sampling interval, retention, privacy class, provenance and measured/estimated status.
2. Reuse the existing SQLite database with additive versioned tables for one installation identity, runtime sessions, idempotent events, metric observations/rollups, lifetime counters, log records, restricted security audit, report jobs/download audit and integration delivery state.
3. Use a bounded low-overhead writer queue with batched transactions and explicit noncritical-event drop counters. Audit, operational-event and SIEM-outbox rows share a transaction; sensitive API settings/token, MCP approval, retention-policy and SIEM destination mutations now include their primary database changes in that transaction. The 14 November call-site review's auth gap is addressed for standalone login success/failure and authorization-denial events by a separate capped private SQLite replay sidecar; queue saturation is counted when the metadata write succeeds, and successful login fails closed when neither store confirms persistence. MCP invocation telemetry now uses a separate per-agent-host SQLite queue capped at 512 rows/2 MiB, with stable invocation IDs and a bounded process-local fallback only when that store is unavailable. Dataset/MCP analytics may still be lost after logged storage failures; host-sample failures warn, leave other sensor writes enabled, and accumulate a process-local count by registered metric until a stable-ID gap event is persisted. A failed gap-event write retries on a later telemetry cycle, but an abrupt process exit before that flush can lose the pending summary. A synthetic four-process test now writes and replays 32 unique auth-denial events without drops. Whole-volume failure, physical disk-full, production filesystem behavior, and broad admin/camera/worker contention remain unverified. Multiple processes use unique event IDs and short transactions.
4. One authorized query/report service backs UI, REST, MCP and CLI. Apply existing admin/token scopes, bounded time ranges, cursor pagination, rate limits and redaction consistently.
5. Add Overview, Metric Explorer, Lifecycle, Hardware & Energy, Log Explorer, Reports and Integrations within current navigation, reusing existing theme, hardware/training services and table/chart patterns.
6. External delivery consumes the same redacted event pipeline, uses TLS, signed requests, bounded batches, retry/backoff and visible delivery/dead-letter state. No external destination is enabled by default.

## Migration and rollback plan

- Before migration, inspect only database path, file size, SQLite version and active readers/writers. Do not copy personal data to an unprotected location.
- Use SQLite's online backup API to make an access-restricted timestamped backup inside the VAOS data directory, verify it opens and passes PRAGMA integrity_check, and document exact restore steps. Do not overwrite or delete the original database.
- Add an explicit schema-version table and ordered migration functions. Migrations are additive first; do not drop or rename existing Feature 8-unrelated data.
- Run upgrade/restore tests against temporary copies of representative schemas. Do not migrate the live user database during implementation.
- Keep new features behind existing admin authentication and keep external integrations off by default. Restore only from a verified pre-migration backup if a migration fails. Rollback must not delete collected historic logs or user records.

## Risk register

| Risk | Severity | Mitigation / gate |
| --- | --- | --- |
| Source/runtime identity | High | Implement against the inspected working tree. P matching version string does not prove which files a running process imported; do not claim the feature is live or restart existing services during implementation. |
| SQLite contention across admin, camera and workers | High | Short batched transactions, bounded queues, WPL/busy handling where compatible, multi-process tests and visible drop counts. |
| Sensitive data leaks through logs, exports or SIEM | Critical | Central redaction before storage; block credentials, capability URLs, biometric material and image bytes; adversarial security tests. |
| Unbounded logs/cardinality exhaust disk or RAM | High | Bounded query windows, pagination, batching, retention, rollups and disk-full tests. Keep lifetime aggregates independent of raw retention. |
| False crash/lifetime totals | High | Unique/idempotent event IDs, explicit session IDs, UTC, heartbeat reconciliation and tests for retry, clock changes and abrupt exit. |
| Unsupported energy shown as measured | High | Sensor detection, provenance, gap/coverage display, omit unsupported values or label estimates. |
| CSV/PDF injection or oversized reports | High | Formula escaping, typed schemas, bounded streaming, async jobs, cancellation, expiry and export audit. |
| SIEM misuse or secret exposure | High | Disabled by default, TLS-only remote endpoints, secret-safe configuration, signature validation, bounded retries and no unverified vendor claims. |
| Telemetry interferes with inference/training | High | Keep writer work off model/GPU paths; synthetic fixtures first; defer host/hardware tests until safe. |

## Acceptance criteria and implementation sequence

1. **Contracts/storage:** metric definitions, additive migration/versioning, installation/session lifecycle, idempotent aggregation, redaction and retention tests.
2. **Shared service:** low-overhead event/log/metric writers, query filters and failure/backpressure behavior.
3. **UI:** Overview, Metric Explorer, lifecycle, Hardware & Energy and Log Explorer; responsive, keyboard-accessible, paginated, searchable, with honest unavailable/empty states.
4. **CLI:** installable vaos command for status/stats/logs/reports/integrations; text/JSON/NDJSON/CSV, piping, documented exit codes and Linux/systemd guidance.
5. **Reports:** central registry and CSV/PDF renderers; async jobs for large exports; exact filters, units, provenance and download audit.
6. **REST/MCP:** versioned, scoped, documented APIs; MCP uses the existing exact-request approval for sensitive exports/changes.
7. **SIEM:** implement signed HTTPS, TLS syslog and OTLP/HTTP JSON behind the existing queue; add tested JSON/NDJSON/CEF/ECS mapping, CEF epoch-millisecond timestamps, bounded history and pending caps, a visible dropped-send count, leased dispatch, bounded DNS resolution and retry/dead-letter status. Defer OCSF until valid actor/source fields exist. Real receiver interoperability remains a release gate.
8. **Validation/docs:** isolated migration/restore, lifecycle/concurrency, privacy/redaction, API/MCP/CLI/report/SIEM tests, browser journeys and measured performance. Update README, user/developer guides, API/MCP references, schema/metric dictionary, changelog, security and rollback docs.
9. **Release gate:** no staging until test results, browser evidence, restore, security review and measured performance pass. Deployment remains a separately approval-gated action.

### Minimum acceptance checks

- Lifetime starts, clean stops, uptime, training jobs/epochs, image/frame counts, API requests and supported inference counts survive process restarts and trace to definitions.
- Event replay does not double-count; ambiguous heartbeat loss is shown as unknown until reconciled.
- Filters reject unsupported dimensions and enforce date, page and query limits; logs redact secrets and paginate stably.
- Non-admin or insufficiently scoped API/MCP/CLI callers cannot read restricted events or export private data.
- CSV injection, PDF layout, large/cancelled jobs, expired downloads, disk full and SIEM outage/retry are tested synthetically.
- Local offline mode works; no external account is required. Unsupported fields show unavailable rather than fabricated zeroes.
- UI and CLI agree with API/service data. Desktop/mobile, keyboard and empty/error/loading states must be checked. Test the seven requested personas against current v1.1.0 scope: researcher uses recorded training metrics instead of Arena comparisons, and beginner creates a camera workflow through existing controls instead of a template gallery. Capture evidence for every journey.

### Report and external action semantics (13 November 2026)

Report creation, cancellation and download use transactional audit coupling. For the irreversible SIEM test-connection send, VAOS persists the attempt before network I/O and persists the result afterward; the result cannot be rolled back after an external receiver has seen it. Authentication/denial coalescing markers are cleared after persistence failures so retries are not suppressed. Real external receiver behavior remains a release test requirement.

### Report queue failure response (13 November 2026)

If a report request and audit commit but local worker submission fails, the API discloses that the request is saved and may remain queued, instructing the caller to inspect Reports before retrying. This avoids falsely claiming a rollback after commit.
