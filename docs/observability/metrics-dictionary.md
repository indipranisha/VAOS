# Observability metric dictionary

The source of truth is `observability_store.METRIC_CATALOGUE`. The API catalogue at `GET /api/admin/observability/metrics` reports the current database availability for each item. “Registered” means a definition exists; it does not guarantee that this installation has collected data.

## Interpretation

- Gauges retain timestamped observations. `aggregation` describes overview/report behavior; it is not a promise that every sample exists.
- Counter updates use event IDs so a replayed event does not double-count.
- Metric observations must link to a stored source event. The API returns timestamp, value, dimensions, provenance, measurement scope and whether the value is estimated.
- Training dimensions include the training job, selected data source, starting model and epoch when provided by the callback.
- Never compare ratios from different validation sets as if they were directly equivalent. VAOS records what the trainer reports; it does not certify model quality.
- Sampling cadence, dimensions and aggregation above mirror the code-owned catalogue; date and other query parameters are offered only where the metric API defines them. Absence of a sample is shown as unavailable, never as a measured zero.
- Privacy classes also mirror the registry. All current metrics are source-reported (`estimated=false`); this describes provenance and does not independently certify trainer metrics or hardware sensors.

## Metric Explorer grouping and time aggregation

The metric catalogue API supplies `series_aggregations` for each metric. The Metric Explorer and series API use that list rather than offering every arithmetic operation for every metric. Raw points remain available. Counter metrics only support **sum** of recorded deltas. Gauge metrics support **average**, **minimum**, and **maximum** bucket values; **sum** is added only for metrics whose registered semantics declare `sum` or `integral`. `app.uptime_seconds` is an interval-union calculation and does not offer bucket aggregation.

Supported UTC bucket widths are one minute, five minutes, one hour, and one day. `group_by` must be one of the metric's registered dimensions. Exact dimension filters are applied before grouping. Grouped dimension values are returned as text so aggregation, exact-filter matching, group counts, chart labels and report dimensions normalize numeric and textual forms consistently. With no grouping dimension selected, bucket values combine all matching dimension values; this is useful for totals but can combine devices, routes, or models, so select a grouping dimension when you need separate series. Each aggregate point includes its bucket timestamp, value, group dimension when selected, source-record count, estimate flag, and explicit aggregate provenance. The API returns at most 1,000 newest points and marks truncation; narrow the time range before interpreting an incomplete view or exporting it. When the returned points contain more than eight groups, the chart limits its plotted series to the eight groups with the most points in that response and explicitly identifies how many groups it omitted; the table and central export retain the full result within their own 1,000-row limit.
